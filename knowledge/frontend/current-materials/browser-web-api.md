## WEB-01. Как HTML превращается в пиксели?

**Ответ.** Браузер получает ресурсы, разбирает HTML и CSS, создаёт DOM и стилевые структуры, вычисляет стили, геометрию layout, команды paint и композицию. Это упрощённая модель: реальные реализации могут распараллеливать и пропускать ненужные этапы.

**Пример.** Изменение ширины блока может потребовать layout зависимых элементов, смена цвета — paint, transform часто позволяет обойти layout, но не гарантирует бесплатную анимацию. Чередование записи размеров и чтения геометрии может форсировать синхронный layout.

```js
// nodes — коллекция DOM-элементов.
const widths = nodes.map(node => node.getBoundingClientRect().width);
nodes.forEach((node, i) => { node.style.width = `${widths[i] + 10}px`; });
```

Сгруппированные чтения и записи уменьшают чередование; эффект проверяется профилем. **Практика:** отличить время JS от layout в trace. **Ошибка:** «Virtual DOM отменяет работу браузера».

## WEB-02. Как распространяется DOM-событие?

**Ответ.** Событие проходит capture, target и, если поддерживается, bubbling. target — исходная цель, currentTarget — элемент текущего обработчика. preventDefault отменяет отменяемое действие браузера, stopPropagation останавливает дальнейшее распространение; это разные операции.

```js
// list — существующий контейнер.
list.addEventListener('click', event => {
  if (!(event.target instanceof Element)) return;
  const button = event.target.closest('button[data-id]');
  if (!button || !list.contains(button)) return;
  console.log(button.dataset.id);
});
```

Делегирование уменьшает количество подписок и работает с добавленными потомками. Не все события всплывают одинаково; Shadow DOM также влияет на путь и retargeting. Passive-обработчик не позволяет отменить default через preventDefault.

**Практика:** почему stopPropagation дочерней кнопки может сломать аналитику родителя? Найди более явный контракт обработки вместо глобального подавления событий.

## WEB-03. Cookies, WebStorage и IndexedDB — что выбрать?

**Ответ.** localStorage/sessionStorage хранят строки и работают синхронно; sessionStorage привязан к сессии вкладки и origin, localStorage сохраняется между сессиями. IndexedDB — асинхронное структурированное хранилище с транзакциями и индексами. Cookies отправляются с подходящими HTTP-запросами по правилам области и политики браузера.

**Пример.** Тема интерфейса — небольшой ключ localStorage; большой офлайн-каталог — IndexedDB; серверная сессия часто использует cookie с соответствующими флагами. Ни одно клиентское хранилище не является надёжной бессрочной базой: квоты, очистка и ошибки должны учитываться.

```js
function saveTheme(theme) {
  try { localStorage.setItem('theme', theme); return true; }
  catch { return false; } // UI продолжает работать без сохранения
}
```

IndexedDB не является разновидностью WebStorage, хотя в исходной матрице стоит под этим названием. **Практика:** опиши миграцию версии схемы IndexedDB и поведение второй открытой вкладки. **Ошибка:** сохранять всё приложение синхронно на каждый ввод.

## WEB-04. Когда нужен Web Worker?

**Ответ.** Worker выполняет JavaScript отдельно от главного потока и не имеет прямого доступа к DOM. Общение идёт сообщениями: данные обычно структурированно клонируются, а переносимые объекты можно передать с передачей владения. Выигрыш зависит от стоимости работы и обмена.

```js
// main.js
const worker = new Worker(new URL('./worker.js', import.meta.url), { type: 'module' });
worker.postMessage([3, 1, 2]);
worker.onmessage = event => console.log(event.data);
// worker.js, отдельный файл:
// self.onmessage = event => self.postMessage(event.data.sort((a, b) => a - b));
```

Пример требует двух файлов. После завершения жизненного цикла вызываем terminate или согласованное закрытие. При передаче ArrayBuffer как transferable исходный буфер может стать detached. Worker не ускоряет сам по себе медленный API и не делает бесплатной передачу гигабайта данных.

**Практика:** выбери порог, при котором сортировка в Worker полезна, и измерь задержку UI отдельно от общего времени операции.

## WEB-05. Чем Service Worker отличается от Web Worker?

**Ответ.** Service Worker — управляемый браузером событийный посредник для своего scope, способный перехватывать запросы и работать с Cache API. Он не является постоянно живущим фоновым процессом и не имеет DOM. Нужны безопасный контекст и явная регистрация.

**Пример.** Для версионированных статических файлов подходит cache-first; для оперативных данных часто network-first или другая согласованная стратегия. Cache API не автоматически соблюдает все правила HTTP-кэша за разработчика. Персональные ответы нельзя бездумно помещать в общий кэш.

Жизненный цикл включает install, ожидание и activate; новый worker не всегда немедленно заменяет управляющий старой страницей. Принудительная активация может смешать старый UI и новые ресурсы.

**Практика:** пользователь после релиза видит старую версию. Проверь управляющий worker, версии cache, HTML и assets, поведение обновления и восстановления. **Ошибка:** лечить каждый релиз советом «очистите всё вручную».

## WEB-06. Как загружаются script, async, defer и ресурсы?

**Ответ.** Обычный классический script без атрибутов может блокировать HTML-парсер. defer для внешнего классического скрипта откладывает выполнение до окончания разбора и сохраняет порядок таких скриптов; async выполняется по готовности и не гарантирует порядок. Модульные скрипты по умолчанию имеют отложенную семантику, но детали async и зависимостей нужно учитывать отдельно.

```html
<script defer src="/app.js"></script>
<img src="/hero.webp" width="1200" height="600" alt="Горы возле Алматы">
<img loading="lazy" src="/below-fold.webp" width="600" height="400" alt="Отель">
```

Главное видимое изображение обычно не стоит лениво откладывать. Preload нужен только ресурсу, который действительно понадобится скоро: лишние подсказки конкурируют за полосу. **Практика:** объясни waterfall страницы с поздно обнаруженным главным изображением.

## WEB-07. Как найти DOM-элемент, изменить текст и подключить обработчик?

**Короткий ответ.** DOM представляет документ узлами. querySelector возвращает первый подходящий элемент или null; textContent меняет текст. addEventListener подписывает на событие. Нужно учитывать момент появления элемента и время жизни подписки.

**Пример по шагам.** Для <button id="save">Сохранить</button> находим кнопку, проверяем null, подписываем click. В обработчике меняем textContent на «Сохранено». Пользовательский текст не нужно вставлять через innerHTML.

**Практика.** Компонент многократно монтируется и добавляет обработчик window. Почему обработчик вызывается несколько раз?
