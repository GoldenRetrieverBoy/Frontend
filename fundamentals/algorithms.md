## ALG-01. Как оценивать сложность?

**Ответ.** Big O описывает рост затрат с размером входа, а не точное время. Уточняю, о каком случае и параметре речь, отдельно оцениваю дополнительную память. Вложенные циклы не всегда O(n²): внутренний размер и суммарная работа имеют значение.

```js
const ids = new Set(items.map(item => item.id));
const selected = other.filter(item => ids.has(item.id));
```

В типичной hash-реализации ожидаемая работа близка к O(n+m), память O(n). Язык не обещает каждой операции Set строгое O(1) в любом движке. Вариант с includes по массиву внутри filter может потребовать O(nm).

**Практика:** сравни поиск пересечения двух списков по 100 000 записей с учётом дублей и памяти.

## ALG-02. Object, Map, Set, tuple и Record — что различается?

**Ответ.** Object удобно представляет запись с полями; Map — коллекцию ключ/значение с произвольными ключами; Set — уникальные значения. У Object ключи — строки или символы. Tuple и Record в TypeScript описывают типы и сами не создают новые runtime-структуры. JSON — формат данных, а не отдельный тип объекта JS.

```ts
const point: [number, number] = [10, 20];
const statuses: Record<string, boolean> = { ready: true };
const cache = new Map<object, string>();
const key = {};
cache.set(key, 'value');
console.log(cache.get({})); // undefined: другой объект
```

WeakMap/WeakSet не удерживают поддерживаемые слабые ключи/значения сильно; их нельзя перечислить как обычную коллекцию. Они подходят метаданным объектов, а не списку, который нужно показать пользователю. Слабые коллекции не дают события «объект собран» для бизнес-логики.

**Практика:** выбери структуры для кэша DOM-метаданных, выбранных id и упорядоченного списка результатов. Не используй обычный объект с произвольными внешними ключами без учёта прототипа.

## ALG-03. Стек, очередь и связный список — где пригодятся?

**Ответ.** Стек — LIFO, очередь — FIFO. Связный список хранит связи узлов; вставка по уже известному узлу может быть дешёвой, но поиск узла требует обхода. Массив лучше использует локальность и проще для большинства UI-сценариев.

```js
const queue = ['root'];
let head = 0;
while (head < queue.length) {
  const item = queue[head++];
  console.log(item);
}
```

Индекс head избегает повторного shift с перемещением элементов; длительно живущей очереди нужна очистка/кольцевой буфер, иначе сохраняются уже обработанные элементы. Стек используется в undo и DFS, очередь — в BFS и диспетчере задач.

**Практика:** проверка сбалансированности скобок стеком. Пустой ввод, неверная закрывающая скобка, незакрытые скобки — обязательные случаи.

## ALG-04. DFS, BFS и рекурсия — как выбрать?

**Ответ.** DFS углубляется по ветке, BFS проходит уровнями. Для дерева оба посещают все узлы за O(V); для графа с adjacency list — O(V+E) при учёте visited. Рекурсия использует стек вызовов и может переполнить его на большой глубине.

```js
function findNode(root, id) {
  const stack = [root];
  while (stack.length) {
    const node = stack.pop();
    if (node.id === id) return node;
    stack.push(...node.children);
  }
  return undefined;
}
```

Пример предполагает дерево без циклов и children у каждого узла. Для произвольного графа нужен visited. Дополнительная память зависит от формы дерева и алгоритма, а не всегда O(log n).

**Практика:** преобразуй плоский список `{id,parentId}` в дерево через Map. Определи поведение для отсутствующего родителя, дубликатов и циклов.

## ALG-05. Как найти кратчайший путь?

**Ответ.** BFS находит кратчайший путь по количеству рёбер в невзвешенном графе. Для неотрицательных весов применим Dijkstra; отрицательные веса нарушают его обычные предпосылки. Храним не только расстояния, но и предшественников для восстановления пути.

**Пример.** A→B стоит 10, A→C — 1, C→B — 1. BFS может предпочесть одно ребро A→B, но минимальная стоимость равна 2 через C. «Самый короткий» требует определения критерия.

**Практика:** для переходов между экранами найди минимальное количество шагов BFS; затем объясни, что изменится, если каждый переход имеет разную стоимость. **Ошибка:** visited при Dijkstra без правильного извлечения минимума.

## ALG-06. Что знать о сортировках и бинарном поиске?

**Ответ.** Insertion sort прост и имеет квадратичный худший случай; merge sort — O(n log n) времени с дополнительной памятью в типичной реализации; quicksort — ожидаемо O(n log n), но O(n²) в худшем случае без защит. Стабильность сохраняет порядок элементов с равным ключом. JS sort мутирует массив, а без comparator сравнивает строковые представления.

```js
const numbers = [10, 2, 1];
console.log([...numbers].sort((a, b) => a - b)); // [1, 2, 10]
function binarySearch(items, target) {
  let left = 0, right = items.length - 1;
  while (left <= right) {
    const middle = left + Math.floor((right - left) / 2);
    if (items[middle] === target) return middle;
    if (items[middle] < target) left = middle + 1;
    else right = middle - 1;
  }
  return -1;
}
```

Бинарный поиск требует согласованно отсортированного входа; O(log n) поиск не отменяет стоимость предварительной сортировки. **Практика:** вернуть первый индекс при дубликатах. Проверь пустой массив и границы.
