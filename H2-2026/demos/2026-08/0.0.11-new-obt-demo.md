## Главный narrative

Релиз улучшает четыре критичных части New OBT:

1. Добавляет новый self-service capability — MICE-заявку прямо на главной.
2. Делает работу с сотрудниками одинаковой во всех ключевых travel flows.
3. Устраняет ошибки выбора пассажиров и данных, которые могут ломать или затруднять бронирование.
4. Выносит тяжёлые картинки и видео Corporate Travel Portal из frontend bundle на C3 CDN.

## Opening на 30–45 секунд

Сегодня показываем точечный релиз 0.0.11. Его смысл не в одном большом экране, а в том, что New OBT становится ближе к нормальному production rollout: меньше внешних переходов, меньше прерываний booking flow и меньше мелких дефектов вокруг пассажиров, документов и поиска.

Основной фокус показа:

- MICE-заявка теперь живёт внутри New OBT, а не во внешней Google Form.
- Добавление и редактирование сотрудника работает одинаково в кабинете и travel flows.
- Семейные и паспортные сценарии в авиа стали безопаснее: дети находятся в поиске, ФИО берётся из документа, длинные имена не ломают selector.
- Тяжёлые media assets вынесены на CDN: production `dist` стал легче, а картинки остались доступны через проверенные CDN URL.

## Что не оверклеймить

- Не говорить, что 0.0.11 уже повысил conversion, GMV или adoption: post-release окна ещё нет.
- Не выдавать Amplitude baseline за A/B или measured impact.
- Не обещать эффект MICE/employee drawer без instrumentation: событий `mice_form_start`, `mice_submit_success`, `employee_drawer_open`, `employee_save_success` пока нет.
- Compact search можно упоминать как broader H2 progress / Q&A, если он не входит в фактический release scope.
- По CDN можно говорить measured technical impact: уменьшение production `dist`, доступность CDN URL и cache headers подтверждены. Не переводить это в LCP/конверсию без route-level замеров.

**Что сделано**

### 2. Единый drawer сотрудника

**Что сделано**

- Добавление и редактирование сотрудника использует одно окно в кабинете, авиа, ЖД и отелях.
- Drawer открывается поверх текущего flow без перехода в кабинет.
- Повторный авиапоиск с другим составом не конфликтует с предыдущим запросом.

**Что показать**

Авиа-поиск → добавить сотрудника → показать тот же drawer, что в кабинете → поменять состав → запустить повторный поиск до завершения предыдущего.

**Capability impact**

Единый employee flow переиспользуется в поиске и бронированиях; устранён race condition повторного поиска.

**Ожидаемый продуктовый эффект**

- меньше прерываний booking flow;
- меньше повторного ввода данных;
- меньше ошибок при смене пассажиров.

### 6. CDN для картинок и видео Corporate Travel Portal

**Что сделано**

- Контентные картинки и видео Corporate Travel Portal вынесены из frontend repository / production bundle в C3 CDN namespace `b2b/corporate-travel-portal`.
- В коде оставлены UI SVG, логотипы и brand marks; тяжёлые raster/video assets больше не едут внутри frontend `dist`.
- Добавлен fallback: travel loader остаётся видимым, если CDN video не загрузилось.
- Добавлен audit `npm run audit:assets`, чтобы контролировать локальные media и CDN-маппинги.
- Проверены все 132 CDN URL.

**Что показать**

Engineering slide / короткий блок с таблицей before/after. Если есть доступ к приложению и DevTools, открыть Corporate Travel Portal и показать, что media грузятся с CDN URL, а не из локального bundle.

**Capability impact**

Тяжёлые картинки и видео вынесены из production frontend artifact. Это снижает размер деплоя и уменьшает риск разрастания локального bundle при добавлении контентных assets.

**Измеренный technical impact**

| Метрика | До | После | Изменение |
|---------|---:|------:|----------:|
| Media в production `dist` | 7,377 MiB | 0,289 MiB | −7,088 MiB / −96,08% |
| `dist` без source maps | 15,314 MiB | 8,215 MiB | −7,099 MiB / −46,36% |
| Полный `dist` | 39,618 MiB | 32,515 MiB | −7,103 MiB / −17,93% |
| Total JS gzip | 2,090 MiB | 2,077 MiB | −13 KiB / −0,59% |

CDN-проверка:

- 132/132 URL ответили `200 OK`;
- 132/132 имеют корректный MIME type;
- 132/132 имеют `ETag`, `Last-Modified` и `Cache-Control: public, max-age=14400`;
- повторный прогон CDN cache: 132/132 `HIT`;
- warm CDN TTFB: mean 168 ms, p50 141 ms, p95 237 ms.

**Задача**

- [CORP-4825](https://app.asana.com/1/1208507351529750/project/1210670407720851/task/1217836666953975)

**Снять после релиза**

- route-level transferred bytes на страницах, где используются media;
- LCP/CLS на реальных сценариях Corporate Travel Portal;
- CDN cache-hit ratio на production traffic;
- ошибки загрузки CDN media и срабатывание fallback loader.

**Speaker notes / заметки к показу**

- Сказать прямо: "Мы выкатили CDN для картинок и видео, чтобы тяжёлый контент не жил внутри frontend bundle".
- Главное число для demo: media в production `dist` уменьшились на 96,08%, с 7,377 MiB до 0,289 MiB.
- Подчеркнуть, что JS/CSS почти не выросли: миграция не добавила заметной стоимости в critical frontend bundle.
- Не обещать ускорение LCP как уже доказанный факт. Формулировка: "artifact стал легче, CDN доступность проверена; route-level performance доберём после production traffic".
