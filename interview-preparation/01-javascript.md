## JS-01. Что такое замыкание?

### Короткий ответ

Замыкание — функция вместе с доступом к лексическому окружению, в котором она создана. Она может обращаться к внешним переменным после завершения внешнего вызова. Сохраняется доступ к переменной, а не только снимок её значения.

```js
function createCounter() {
  let count = 0;
  return function increment() {
    return ++count;
  };
}
const first = createCounter();
const second = createCounter();
console.log(first());  // 1
console.log(first());  // 2
console.log(second()); // 1
```

Каждый вызов createCounter создаёт своё окружение. Возвращённая функция имеет доступ к count из своего вызова. Поэтому два счётчика независимы.

### Нюанс: вычисленное значение

```js
let count = 0;
const message = `Count: ${count}`;
const increment = () => ++count;
const print = () => console.log(message);
increment();
print(); // Count: 0
```

Строка message вычислена один раз. Изменение count не пересчитывает её. Для актуального значения строку нужно формировать при вызове print.

### Уточнения и практика

- Почему обработчики в цикле с var видят общую переменную, а с let могут видеть отдельную привязку каждой итерации?
- Как замыкание используется в debounce?
- Переделай пример так, чтобы print показывал актуальный count.
- Замыкание само по себе не является утечкой: нужна ненужная, но сохраняющаяся достижимость данных.

## JS-02. От чего зависит this?

### Короткий ответ

У обычной функции this определяется способом вызова. При object.method() это объект вызова. При отдельном вызове в строгом режиме — undefined. Стрелка собственного this не создаёт и использует внешний; call/apply/bind его не переопределяют.

```js
"use strict";
const user = {
  name: "Игнат",
  greet() { return `Привет, ${this.name}`; },
};
console.log(user.greet()); // Привет, Игнат
const greet = user.greet;
// greet(); // TypeError: обращение к name у undefined
const bound = user.greet.bind(user);
console.log(bound()); // Привет, Игнат
```

Присваивание функции другой переменной не сохраняет объект вызова. bind создаёт функцию с привязанным this. Обёртка `() => user.greet()` тоже работает, но заново читает user.greet при каждом вызове.

### Практика

Объясни разницу между bound и обёрткой, если после их создания заменить user.greet. Затем разбери стрелку внутри метода и стрелку, записанную непосредственно в свойство объекта. Сам объектный литерал не создаёт для стрелки отдельный this.

Типичная ошибка: «this — объект, где функция объявлена». Для обычной функции это неверно.

## JS-03. Как работает event loop в браузере?

### Короткий ответ

Синхронный код выполняется в стеке вызовов. Таймеры вызывают обработчики в задачах. Реакции Promise и продолжения после await выполняются через микрозадачи. После завершения текущей задачи браузер опустошает очередь микрозадач; далее может появиться возможность обновить отображение и выполнить следующую задачу. Отрисовка не гарантирована после каждой задачи.

```js
console.log("A");
setTimeout(() => console.log("B"), 0);
Promise.resolve().then(() => console.log("C"));
console.log("D");
// A D C B
```

A и D — синхронные вызовы. C — микрозадача. B — обработчик таймера в последующей задаче. Нулевой таймаут не означает немедленное исполнение и не прерывает синхронный код.

```js
Promise.resolve().then(() => {
  console.log("A");
  queueMicrotask(() => console.log("B"));
});
Promise.resolve().then(() => console.log("C"));
// A C B
```

Во время A микрозадача C уже ожидает. B добавляется после неё. Цепочка постоянно создаваемых микрозадач может задерживать ввод и отрисовку. Promise не переносит тяжёлое вычисление в другой поток.

### Текущая задача — сначала ответ без запуска

```js
console.log("1");
async function run() {
  console.log("2");
  await Promise.resolve();
  console.log("3");
}
setTimeout(() => console.log("4"), 0);
run();
Promise.resolve().then(() => console.log("5"));
console.log("6");
```

Назови порядок и объясни момент приостановки run. Ответ намеренно не раскрыт до самостоятельной попытки.

## JS-04. Блокирует ли await поток?

### Короткий ответ

await приостанавливает текущую async-функцию, а не весь поток. До первого await тело выполняется синхронно. Синхронное тяжёлое вычисление внутри async всё равно блокирует поток.

```js
async function example() {
  console.log("A");
  await Promise.resolve();
  console.log("B");
}
example();
console.log("C");
// A C B
```

### Независимые операции

```js
// getUser и getOrders — условные функции, возвращающие Promise.
const [user, orders] = await Promise.all([getUser(), getOrders()]);
```

Оба вызова начинаются без ожидания друг друга. Promise.all объединяет результаты, а не сам запускает функции. Если getOrders нужен user.id, зависимость требует ожидания user.

При ошибке одной операции итоговый Promise.all отклоняется, но остальные операции автоматически не отменяются. allSettled позволяет получить исход каждой операции независимо от ошибок.

### Практика

Спроектируй загрузку обязательного профиля и необязательных рекомендаций. Затем объясни, почему запуск сразу 10 000 запросов может быть проблемой и где нужен ограничитель конкурентности.

## JS-05. Как устранить гонку ответов поиска?

### Короткий ответ

Запросы могут завершаться в другом порядке, чем запускались. Обновлять интерфейс должен только актуальный запрос. Предыдущую операцию можно дополнительно отменять. Debounce уменьшает число запросов, но не гарантирует порядок ответов.

```js
function createSearch(renderResults, showError) {
  let latestRequestId = 0;

  return async function search(query) {
    const requestId = ++latestRequestId;
    try {
      const response = await fetch(
        `/api/search?q=${encodeURIComponent(query)}`
      );
      if (!response.ok) throw new Error(`HTTP ${response.status}`);
      const results = await response.json();
      if (requestId !== latestRequestId) return;
      renderResults(results);
    } catch (error) {
      if (requestId !== latestRequestId) return;
      showError(error);
    }
  };
}
```

Счётчик отдельный для каждого созданного поискового контроллера. Проверяем актуальность и успешного ответа, и ошибки: старая ошибка не должна перекрыть новый результат. Пример показывает защиту от гонки; очистка при уничтожении интерфейса и loading здесь ещё не реализованы.

### Практика

Добавь loading так, чтобы finally старого запроса не выключал индикатор нового. Затем добавь AbortController и инвалидирование при закрытии интерфейса. Объясни, почему отмена на клиенте не гарантирует прекращения серверной обработки.

## JS-06. Почему возникают утечки памяти?

### Короткий ответ

Сборщик мусора может освобождать недостижимые объекты. Утечка возникает, когда данные приложению уже не нужны, но всё ещё достижимы по ссылкам. Точный момент сборки не гарантирован. Циклические ссылки сами по себе не мешают собрать недостижимую группу объектов.

```js
function mountWidget() {
  const data = new Array(100_000).fill("item");
  function handleResize() { console.log(data.length); }
  window.addEventListener("resize", handleResize);
  return () => window.removeEventListener("resize", handleResize);
}
const cleanup = mountWidget();
// При уничтожении виджета:
cleanup();
```

Пока подписка существует, window удерживает обработчик, а обработчик — доступ к data. Снятие подписки устраняет этот путь; другие сохранённые ссылки также могут удерживать данные. Само удаление DOM виджета не снимает подписку на window.

Частые причины: подписки, интервалы, неограниченный кэш, ссылки на удалённые DOM-узлы. Диагностика: повторить создание/удаление интерфейса, сравнить снимки памяти, изучить удерживаемые объекты и пути ссылок. Одного роста памяти недостаточно для доказательства утечки.

### Практика

Объясни, почему `a = null` не освобождает объект, если `b` всё ещё на него ссылается. Предложи эксперимент, отличающий ожидаемый рост кэша от утечки после закрытия компонента.

## JS-07. Какие типы есть в JavaScript и как работает сравнение?

**Ответ.** Примитивы: undefined, null, boolean, number, bigint, string, symbol. Остальное — объекты, включая функции. Примитивное значение нельзя изменить внутри; переменной можно присвоить новое. Объекты сравниваются по идентичности. `===` не приводит разные типы друг к другу; `==` использует правила приведения, поэтому для обычной прикладной логики удобнее явное преобразование и `===`.

```js
console.log(typeof null); // "object": историческая особенность
console.log([] === []); // false: разные объекты
console.log(0 == false); // true
console.log(0 === false); // false
console.log(Number.isNaN(NaN)); // true
console.log(NaN === NaN); // false
console.log(Object.is(NaN, NaN)); // true
console.log(Object.is(0, -0)); // false
console.log(Boolean("false")); // true: непустая строка
console.log("" || "default"); // "default"
console.log("" ?? "default"); // ""
```

`??` заменяет только null/undefined, `||` — любое falsy-значение. Это существенно для цены 0 и пустого текста. `Number` использует двоичную плавающую точку: `0.1 + 0.2 !== 0.3`. Для денег выбирают целые минимальные единицы в допустимом диапазоне или согласованную десятичную арифметику. BigInt нельзя просто смешивать с Number в арифметике.

**Уточнение.** Почему проверка `if (price)` теряет бесплатный тариф? Она смешивает отсутствие цены и 0.

**Практика.** Напиши нормализацию строкового ввода возраста: отличи пустое значение, нечисловую строку и допустимый 0. Не используй автоматическое превращение пустой строки в 0 без проверки.

## JS-08. Что такое hoisting и TDZ?

**Ответ.** До исполнения выражений движок создаёт привязки объявлений. `var` инициализируется undefined, function declaration обычно доступна вместе с функцией. Привязки let/const существуют с начала блока, но до выполнения объявления не инициализированы: это temporal dead zone. Поэтому говорить «let вообще не поднимается» неточно.

```js
console.log(a); // undefined
var a = 1;
// console.log(b); // ReferenceError
let b = 2;
const item = { count: 1 };
item.count = 2; // разрешено: привязка item не изменилась
```

У var функциональная область видимости, у let/const — блочная. const запрещает переприсваивание привязки, а не изменение объекта. Даже `typeof variable` выдаёт ReferenceError для переменной в TDZ, хотя для необъявленного имени возвращает "undefined".

**Практика.** Объясни ошибку: `let x = 1; { console.log(x); let x = 2; }`. Ожидаемое объяснение: внутреннее объявление затеняет внешнее во всём блоке, чтение попадает в TDZ.

## JS-09. Как устроены прототипы, new и классы?

**Ответ.** При чтении свойства движок сначала проверяет собственные свойства объекта, затем его цепочку прототипов до null. `new` создаёт объект, связывает его с prototype конструктора и вызывает конструктор с новым this; явно возвращённый объект может заменить результат. Классы используют прототипный механизм, но добавляют собственные правила, включая строгий режим и необходимость new.

```js
class User {
  #name;
  constructor(name) { this.#name = name; }
  greet() { return this.#name; }
  static fromName(name) { return new User(name); }
}
const user = User.fromName("Игнат");
console.log(Object.hasOwn(user, "greet")); // false
console.log(Object.getPrototypeOf(user) === User.prototype); // true
```

greet лежит на прототипе и разделяется экземплярами; static вызывается на классе. Поле #name ограничено правилами приватных полей языка. `prototype` конструктора и внутренний прототип экземпляра — разные понятия.

**Ошибка.** Стрелка в поле экземпляра создаётся для каждого экземпляра; это не тот же вариант, что общий метод на прототипе.

**Практика.** Объясни, что произойдёт, если экземпляру присвоить собственный greet, а затем удалить его: чтение снова найдёт метод на прототипе.

## JS-10. Что копируют spread и structuredClone?

**Ответ.** Присваивание объекта копирует значение ссылки. Spread создаёт новый объект с поверхностно скопированными собственными перечислимыми свойствами: вложенные объекты остаются общими. structuredClone глубоко копирует поддерживаемые типы, включая циклические графы, но не является универсальным клонированием функций, DOM и произвольных экземпляров классов.

```js
const original = { address: { city: "Алматы" } };
const copy = { ...original };
copy.address.city = "Астана";
console.log(original.address.city); // Астана
const independent = {
  ...original,
  address: { ...original.address, city: "Алматы" },
};
```

JSON stringify/parse не универсальная замена: теряются или преобразуются некоторые значения, циклы не поддерживаются. Иммутабельное обновление обычно копирует только путь до изменённого узла, сохраняя остальные ссылки.

**Практика.** Обнови один заказ в массиве без мутации исходного массива и заказа. Проверь, что ссылки неизменённых заказов остались прежними.

## JS-11. Что такое чистая функция и когда допустима мутация?

**Ответ.** Чистая функция для одинаковых входов даёт одинаковый результат и не создаёт наблюдаемых внешних побочных эффектов. Это упрощает тестирование и композицию. Сеть, DOM, логирование и запись в хранилище — эффекты; их полезно отделять от расчётов.

```js
const total = items => items.reduce((sum, item) => sum + item.price, 0);
const sorted = items => [...items].sort((a, b) => a.price - b.price);
```

`items.sort()` меняет внешний массив. Сортировка новой локальной копии не меняет вход. Локальная мутация внутри алгоритма допустима, если не нарушает внешний контракт; иммутабельность не требует копировать всё на каждом шаге. Декларативный код описывает желаемый результат, императивный — последовательность действий; функциональный подход делает акцент на функциях и композиции.

**Практика.** Раздели функцию «прочитать корзину, посчитать скидку, отправить аналитику» на чистый расчёт и оболочку с эффектами. Назови входы расчёта, включая время, если скидка зависит от даты.

## JS-12. Как распространяются ошибки в Promise?

**Ответ.** Promise бывает pending, fulfilled или rejected. then возвращает новый Promise: возвращённое значение продолжает успешную цепочку, throw переводит её в ошибку, возвращённый Promise определяет последующий исход. catch может восстановить успешное выполнение. finally обычно сохраняет исход, но его собственный throw или отклонённый Promise заменит исход ошибкой.

```js
Promise.resolve(2)
  .then(value => { throw new Error(String(value)); })
  .catch(() => 10)
  .finally(() => console.log("cleanup"))
  .then(console.log); // cleanup, затем 10
```

Исполнитель `new Promise(executor)` запускается синхронно. race принимает исход первого завершившегося участника; any — первое успешное завершение, а если все отклонены, отклоняется с AggregateError. all сохраняет порядок входов в результатах, независимо от порядка завершения. Ни один из этих методов сам по себе не отменяет оставшиеся операции.

**Практика.** Почему `try { setTimeout(() => { throw Error(); }, 0); } catch {}` не ловит ошибку обработчика? К моменту обработчика исходный try уже завершён; обработка нужна в соответствующей асинхронной цепочке.

## JS-13. Чем debounce отличается от throttle?

**Ответ.** Debounce откладывает вызов до паузы в событиях; throttle ограничивает частоту вызовов во время потока событий. Нужны явные договорённости о первом/последнем вызове и отмене.

```js
// Вариант trailing-only: выполняется после паузы.
function debounce(fn, delay) {
  let timer;
  function wrapped(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  }
  wrapped.cancel = () => clearTimeout(timer);
  return wrapped;
}
```

Обычная wrapped получает this вызова, стрелка таймера сохраняет его; rest сохраняет аргументы. Такой вариант не возвращает будущий результат fn вызывающему коду и не обрабатывает отклонение Promise, если fn асинхронна: её контракт должен это предусматривать.

**Практика.** Добавь flush и тесты с управляемыми таймерами. Для ограничения конкурентности опиши очередь: запускаем не больше N операций, после завершения каждой берём следующую; отдельно определяем поведение при ошибке и отмене.

## JS-14. Как работают ES-модули?

**Ответ.** Модули имеют собственную область видимости, выполняются в строгом режиме и связываются через import/export. Импорты — доступ к экспортируемым привязкам, а не обычные копии значений. Статические импорты позволяют построить граф зависимостей до исполнения; dynamic import возвращает Promise и может дать отдельный загружаемый чанк при сборке.

```js
// counter.js
export let count = 0;
export function increment() { count++; }
// consumer.js
// import { count, increment } from './counter.js';
// increment(); console.log(count); // 1
```

Импортирующий модуль не может переприсвоить импортированную привязку. При цикле зависимости иногда работают, но раннее чтение ещё не инициализированной привязки может дать ошибку. Решение — пересмотреть границы или вынести общий контракт, а не бездумно менять порядок импортов.

**Практика.** Раздели два модуля, которые импортируют друг друга ради общей константы. Объясни разницу между динамическим импортом и обычным вызовом функции.

## JS-15. Зачем Proxy, Symbol и генераторы?

**Ответ.** Proxy перехватывает операции над объектом; Reflect предоставляет стандартные операции, удобные для делегирования с корректным receiver. Symbol создаёт уникальные ключи, а well-known symbols задают протоколы, например итерацию. Генератор приостанавливается на yield и возвращает итератор.

```js
const target = { count: 1 };
const proxy = new Proxy(target, {
  get(object, key, receiver) {
    console.log("read", key);
    return Reflect.get(object, key, receiver);
  },
});
console.log(proxy.count); // read count, затем 1
function* range(end) {
  for (let i = 0; i < end; i++) yield i;
}
console.log([...range(3)]); // [0, 1, 2]
```

Proxy должен соблюдать инварианты языка; он не означает автоматическую безопасность или приватность. Генератор вычисляет по запросу, но spread сразу потребляет весь итератор. Symbol не является секретом: символические свойства можно обнаружить специальными API.

**Практика.** Напиши ленивый обход дерева через генератор и останови потребление после первого найденного узла. Объясни, какой расход памяти останется у стека обхода.

## JS-16. Как проектировать обработку ошибок?

**Ответ.** Разделяю ожидаемые бизнес-исходы и неожиданные технические ошибки. Обрабатываю ошибку на уровне, который может принять решение: повторить, показать корректное состояние или прекратить операцию. Не заменяю любую ошибку пустым массивом, иначе «данных нет» станет неотличимо от сбоя.

```js
async function loadUser(id) {
  try {
    const response = await fetch(`/api/users/${encodeURIComponent(id)}`);
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    return await response.json();
  } catch (cause) {
    throw new Error("Не удалось загрузить пользователя", { cause });
  }
}
```

cause сохраняет исходную причину; пользовательский текст не обязан содержать диагностические детали. В лог добавляем контекст операции и идентификатор релиза, исключая токены и чувствительные данные. Отмена запроса может быть штатным исходом, а не поводом показывать красную ошибку.

**Практика.** Раздели реакции UI на 401, 403, 404, 429, 500 и отмену. Объясни, какие операции можно повторять без риска дублирования.

## JS-17. Что нужно знать о JIT и движке?

**Ответ.** Движок разбирает исходник и исполняет его; конкретные движки используют интерпретацию и несколько уровней компиляции. JIT может оптимизировать часто выполняемый код на основе наблюдений и отменять оптимизацию, когда предположения нарушены. Это детали реализации, а не гарантии стандарта JavaScript.

**Пример.** Микробенчмарк сложения чисел не доказывает ускорение страницы: время приложения может уходить в layout, сеть или создание DOM. Сначала получаю профиль реального сценария, нахожу горячий участок, меняю алгоритм или объём работы и сравниваю одинаковые условия. Тяжёлую задачу можно разбить на части или вынести в Worker с учётом стоимости обмена данными.

**Уточнение.** «Нужно ли писать весь код под скрытые классы V8?» Нет: знание помогает объяснить профиль, но неподтверждённые микрооптимизации ухудшают читаемость без доказанного результата.

**Практика.** Составь эксперимент для сортировки 100 000 элементов: прогрев, несколько запусков, одинаковые данные, время вычисления отдельно от рендера, влияние памяти.
