# Подготовка к техническому собеседованию Frontend Middle 3

## Цель

Последовательно разобрать каждый блок: понять механизм, написать код, найти ошибку и обосновать решение. Подготовка опирается на лист `TechSkills Frontend` файла «Технические потребности для разработчиков (back&front&mobile).xlsx», столбец H (Mid3), с сохранением требований предыдущих уровней.

Источник требований: внутренняя матрица «Технические потребности для разработчиков (back&front&mobile).xlsx».

В матрице 124 технические строки с отметкой `+` для Mid3. Это не количество вопросов: крупные строки раскрываются несколькими вопросами. Учебные упражнения, последовательность и критерии ниже — наша методика, а не официальная шкала работодателя.

## Как занимаемся

1. Берём один вопрос из текущего блока. Не проходим весь блок одним большим сообщением.
2. Ты сначала пробуешь ответить своими словами. «Не знаю» — нормальный результат диагностики.
3. Разбираем короткий ответ для интервью, внутренний механизм и пример по шагам.
4. Проверяем понимание изменённым примером, отладкой или задачей с кодом.
5. Обсуждаем ограничения, альтернативы и уточнения уровня Middle 3.
6. Записываем результат и пробелы в журнал. Прочитанная теория не считается освоенной темой.
7. Возвращаемся к вопросу через несколько занятий. Ориентир повторения: 2, 7 и 21 день, без автоматического расписания.
8. После блока проводим мини-собеседование. Если основа не усвоена, закрепляем её перед переходом дальше.

Для сложного вопроса допускается несколько занятий. Срок собеседования и доступные часы пока неизвестны, поэтому календарные даты не назначены.

## Границы и особенности источника

- C1:E1 в исходной матрице сохранены как даты; предполагаемое соответствие Junior 1–3 не считаем подтверждёнными подписями.
- Node.js для автоматизации изучаем обязательно. Поддержку SSR/BFF, серверное профилирование и Graphite углубляем при наличии такого стека в команде.
- Clean Architecture, DDD и отдельный пункт REST API находятся в TODO исходника. Не выдаём их за утверждённые требования Mid3.
- Паттерны «за пределами» указанных в матрице сайтов не имеют закрытого перечня. Выбираем примеры с объяснимой практической пользой.
- INP заменил FID в Core Web Vitals; учим актуальные LCP, INP и CLS. Источник: https://web.dev/blog/inp-cwv-march-12
- X-XSS-Protection разбираем как устаревший заголовок, с ограничениями. Источник: https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/X-XSS-Protection
- Версионные детали инструментов проверяем по официальной документации во время соответствующего блока.

## Когда вопрос освоен

- Можешь объяснить механизм без чтения готового ответа.
- Предсказываешь результат нового примера и объясняешь причину.
- Применяешь знание в небольшой задаче или диагностике.
- Называешь хотя бы одно ограничение или типичную ошибку.

Оценки: 0 — не знаком; 1 — узнаю термин; 2 — объясняю стандартный случай; 3 — применяю и диагностирую самостоятельно; 4 — разбираю сложные случаи и обосновываю альтернативы. Оценку ставим по ответам, не авансом. Не каждой теме нужна одинаковая глубина.

## Текущая точка и продолжение

В чате даны объяснения первых шести вопросов JS, но самостоятельные ответы ещё не проверены. По умолчанию начинаем последовательное прохождение с JS-01; задача JS-03 сохранена для проверки event loop.

Чтобы продолжить в новом разговоре: «Открой README.md и roadmap/progress.md. Продолжим с текущего вопроса. Задавай по одному вопросу, сначала дождись моего ответа, затем объясни ошибки, покажи пример и дай небольшую практику. Отмечай только подтверждённый прогресс».

Во время занятий не нужно сразу читать ответы всего блока: сначала вопрос и попытка, затем разбор. Неизвестные ответы разбираем с нуля. Сложную тему можно разделить на несколько встреч, сохранив её ID.
